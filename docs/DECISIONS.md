# Архитектурные решения

## 2026-10-01 — Управление из Claude Code через CLI, без артефакта и без MCP
Артефакт — страница на claude.ai в песочнице, до локального REAPER не дотянется. Интерфейс
для сведения уже есть — сам REAPER. CLI вызывается из любой папки трека обычной командой.
Отвергнуто: артефакт (нет доступа к локальной машине), MCP-сервер (в Claude Code ничего не
добавляет к CLI, а отлаживать сложнее).

## 2026-10-01 — Мост — Lua-скрипт в REAPER, обмен через файлы
Lua встроен в REAPER и даёт весь ReaScript API без установки чего-либо. Сокетов в Lua
REAPER нет, файлы с атомарным переименованием — самый простой надёжный канал.
Отвергнуто: веб-интерфейс REAPER и OSC (малая часть API), reapy/Python ReaScript (нужна
настройка Python внутри REAPER), правка .rpp на диске (не живое состояние, конфликт с
открытым проектом).

## 2026-10-01 — Мост выполняет произвольный Lua, а не фиксированный набор команд
Пакет действий — несколько вызовов `rx.*` в одном запросе: один поход в REAPER, один
undo-блок. Набор функций растёт в `lib.lua` без изменения протокола и перезапуска моста.
Отвергнуто: свой язык команд в CLI (каждое новое действие — правка в трёх местах).

## 2026-10-01 — Состояние читается по запросу, не по расписанию
Данные всегда свежие; полный дамп каждые N секунд грузил бы главный поток REAPER, а
большая его часть не нужна. Изменения между запросами видны по счётчику `rev`.

## 2026-10-01 — На диск без потерь, в вывод — сжато
Владельцу нужна высокая точность сохранённых данных, Claude — мало токенов. Снимки хранят
родные чанки REAPER целиком; команды печатают сводку и отличия от значений по умолчанию.

## 2026-10-01 — Правки применяются сразу, одним undo-блоком
Проверить правку можно только на слух, откат — один шаг. Заранее спрашивать только про
роутинг, удаление и мастер-шину. При ошибке посреди правки мост сам откатывает блок.

## 2026-10-01 — Снимки — чанки треков по хешу содержимого
Чанк восстанавливает трек точно, даже когда undo уже недоступен. Хранение по хешу делает
снимок до и после каждой правки дешёвым: меняется обычно один трек.
Отвергнуто: копия .rpp на каждую правку (на диске — последнее сохранённое, а не живое
состояние; нельзя вернуть один трек).

## 2026-10-01 — Значения параметров ставятся подбором по показанию плагина
Общий способ для любых плагинов без ручных таблиц соответствия. Профили плагинов (какие
10–15 параметров из сотен значимы) остаются нужны, но для чтения, а не для записи.

## 2026-10-01 — Каталог плагинов — из списков REAPER, сверенных с диском
REAPER уже сканирует папки плагинов и знает имена, под которыми их можно добавить.
Самостоятельный обход папок дал бы файлы, но не имена и не категории.
Выбор плагина для правки: сначала то, что уже стоит на дорожке, затем подходящий из каталога.

## 2026-10-01 — Стемы — штатным рендером REAPER с подменой настроек
Нужен звук после плагинов и фейдера; audio accessor даёт только сигнал до плагинов.
Настройки рендера проекта сохраняются и возвращаются, формат — 32-bit float, чтобы видеть
превышения 0 дБFS на стемах.
Отвергнуто: запись в реальном времени (медленно), чтение аудио из Lua (до плагинов).

## 2026-10-01 — Маскирование — направленное, по полосам, важным для накрытого
Первый вариант («оба стема звучат в полосе с близким уровнем») находил шум на −51 дБ и
пропускал бочку под басом, который громче на 20 дБ. Полезный вопрос — «чем накрыто то,
что для этого трека главное».

## 2026-10-01 — Параметры плагина показываются только отличные от умолчания
Заменяет ручные «профили плагинов»: работает для любого плагина без описания. Умолчания
берутся с чистого экземпляра на временном треке, след стирается откатом undo-блока.
Отвергнуто: ручные списки значимых параметров на каждый плагин.

## 2026-10-01 — Служебные действия не оставляют записей в undo
Запись «Add FX» от служебного действия легла поверх чужой правки — `reamix undo` отказался
бы её откатывать. Всё, что меняет проект временно, идёт через `rx.scratch`.

## 2026-10-01 — Райдинг — поправка к существующей кривой, цель — медиана самого трека
Абсолютная запись стёрла бы автоматизацию, нарисованную руками. Цель «относительно микса»
точнее по смыслу, но требует рендера микса без трека; пока — выравнивание самого трека.

## 2026-10-01 — Откат записывается в журнал правок отдельной строкой
Журнал только дополняется: видно и правку, и то, что её откатили.

## 2026-10-01 — Сравнение до/после — через undo/redo, с блокировкой правок
Восстановление треков из снимков перезагружало бы плагины и щёлкало. Undo/redo мгновенны,
но правка в состоянии «до» живёт только в redo — поэтому, пока её слушают, мост отклоняет
всё, что создало бы новую запись в истории.
Отвергнуто: переключение восстановлением чанков; хранение отметки в файле проекта.

## 2026-10-01 — Показание плагина спрашивается без изменения параметра
«Поставить и прочитать» на CLAP запаздывало и врало. `TrackFX_FormatParamValueNormalized`
работает во всех форматах и не оставляет следов. Запись значения проверяется отдельно.

## 2026-10-01 — Данные пользователя — в `~/.reamix`, а не в репозитории
Инструмент раздаётся другим людям: каталог плагинов, кэш умолчаний и предпочтения у
каждого свои. В репозитории — только код, шаблоны и документация. Только macOS, русский язык.

## 2026-10-01 — Защита от правки чужого проекта
CLI передаёт текущую папку, мост отказывает, если активный проект REAPER лежит не в ней.
Иначе при нескольких вкладках правка уйдёт не в тот трек. Обход — `--any-project`.

## 2026-10-01 — Документация трека по той же схеме, что в проектах с кодом
CLAUDE.md + docs/CURRENT.md, DECISIONS.md, architecture.md в папке трека. В неё не пишется
то, что читается из REAPER: записанные уровни устареют после первого движения фейдера.

## 2026-10-01 — Импорт из Ableton читает файл .als, а не спрашивает Ableton
В `.als` лежит всё: клипы, варп, автоматизация, состояние каждого плагина. Работает без
запущенного Ableton и одинаково у всех.
Отвергнуто: скрипт внутри Ableton (его API не отдаёт состояние плагинов и автоматизацию
аранжировки); обменные форматы (Live не пишет DAWproject; AAF и готовые конвертеры плагины
не несут).

## 2026-10-01 — Проект REAPER пишется текстом, блоки плагинов собирает живой REAPER
Дорожки, айтемы и огибающие — простой текст, проверяемый тестами без REAPER. Блок плагина
(заголовок с раскладкой входов) знает только REAPER: цепочка собирается на временном треке и
забирается из чанка трека.
Отвергнуто: строить весь проект через API (медленно, сотни вызовов); писать блоки плагинов
самим (заголовок у каждого плагина свой).

## 2026-10-01 — Верстак импорта — пустая вкладка, которую открывает человек
Плагины нельзя собирать в открытом проекте пользователя: остаются записи в undo, а упавший
плагин уносит несохранённую работу. Открывать вкладку самому тоже нельзя: «New project tab»
показывает модальное окно свойств проекта, мост на нём встаёт.
Отвергнуто: временный трек в открытом проекте с откатом (`rx.scratch`) — экземпляр плагина,
созданный и удалённый за один вызов, уронил REAPER (Hammer Mk2: отложенный обработчик
сработал после удаления); открытие готового проекта в новой вкладке самим мостом.

## 2026-10-01 — ARA-плагины и родные устройства Ableton не подменяются
ARA-плагин (Melodyne, Vovious) в REAPER работает через ARA и состояние из Ableton не
примет; второй такой на дорожке вызывает модальное окно. Родных устройств в REAPER нет.
Конвертер их не ставит и не подбирает замену сам: перечисляет в отчёте, параметры родных
устройств кладёт в `native.json`. Замену делает Claude вместе с человеком, на слух.
Точный путь для таких дорожек — заморозка в Ableton: конвертер берёт её звук.

## 2026-10-02 — Основной вход — мультитрек, а не перенос проекта
Владелец сводит в REAPER, а пишет в другой программе: ему нужен отрендеренный мультитрек,
а не живые плагины и клипы. Рендер делает сама программа-источник — звук точный, и не
важно, Ableton это или нет. Перенос `.als` с плагинами остаётся запасным путём.
`.als` в папке мультитрека — только источник темпа, размера, регионов и подсказка по группам.

## 2026-10-02 — Раскладку по папкам решает Claude, код только собирает
Что за дорожка и в какую шину её класть, по имени файла понятно не всегда (`new`, `+12`);
правила в коде были бы хрупкими. Осмотр даёт измерения (спектр, crest, где звучит) и
черновик, Claude пишет раскладку текстом и согласует с человеком, сборка проверяет формальное.
Отвергнуто: автоматическая классификация по ключевым словам в именах.

## 2026-10-02 — Проект трека из мультитрека лежит в reaper/, сессия — в папке трека
Человек открывает Claude там, где лежат файлы; документация трека — там же. Проект и его
служебная папка — в `reaper/`, чтобы не мешаться с мультитреком. Команды находят проект
сами: защита от чужого проекта сверяет активный проект с `reaper/`.

## 2026-10-02 — После сборки из мультитрека анализ делается, но не пересказывается
Сырой материал не сведён: анализ найдёт маскирование и перекосы громкости везде, и список
«проблем» только шумит. Анализ нужен Claude как точка отсчёта (и в кэш); человеку — один
вопрос: какая первая задача с треком.

## 2026-10-02 — Сведение идёт по этапам, порядок задаёт скилл
Владелец не специалист по сведению: ему нужен порядок работ, а не «какая первая задача».
Этапы: сборка → замысел → монтаж → тембр и динамика → пространство → автоматизация →
проверка и финал. Перед этапом — 3–5 вопросов о нём, в конце — отчёт, вердикт и снимок.
Номер этапа хранится в `docs/CURRENT.md` трека. Всё это — текст в скилле и шаблонах, кода нет.
Это заменяет «один вопрос о первой задаче» после сборки: теперь там вопросы о замысле.
Что уточнено против первого плана владельца:
- фаза и выравнивание — до баланса: полярность и сдвиги меняют уровень низа в сумме;
- бас к бочке по транзиентам не двигается: разные партии, сдвиг меняет грув. Выравниваются
  микрофоны одного источника и сэмплы к живым ударам;
- запас под мастеринг закладывается уровнями на этапе монтажа (пики мастера около −6 dBFS),
  а не мастер-фейдером в конце;
- итог — всегда премастер без лимитера; мастеринг и громкая версия — только по просьбе:
  этот шаг сильнее всех зависит от ушей и комнаты;
- добавлены автоматизация (после пространства) и проверка перед выгрузкой.
Отвергнуто: команда `reamix stage` и состояние этапа в коде — этап меняет человек словом,
а помнит его документация трека.

## 2026-10-02 — Гейн-стейджинг: трим первым плагином, плагины не меняют уровень
Владелец хочет, чтобы плагины работали на «комфортном» уровне. Это −18 dBFS по среднему
(0 VU, калибровка эмуляций аналога), пики не выше −6 dBFS. На этапе монтажа, до баланса,
на каждую дорожку первым плагином ставится `JS:utility/volume` с поправкой; дальше каждый
плагин отдаёт тот же уровень, что получил, а громкость в миксе меняет только фейдер.
Меряется существующим `reamix analyze` по самой громкой части, пока плагинов нет: стем
тогда равен источнику. Средний уровень берётся как LUFS (он не считает паузы), у ударных
решают пики, у низких инструментов — `TP − crest`: K-взвешивание занижает низ.
Отвергнуто: громкость айтема вместо плагина — владелец просил плагин, его видно в цепочке;
отдельная команда `reamix gain` — замер до плагинов на дорожке с обработкой требует их
обхода, а в основном флоу (мультитрек, плагинов ещё нет) хватает анализа.

## 2026-10-02 — Гейн-стейджинг получил команды: reamix trim и reamix gain
Через `reamix analyze` сверка уровня шла в несколько заходов: анализ до правки, анализ
после, сравнение на глаз, заодно рендер всего микса; поправки трима Claude считал вручную.
Теперь `reamix gain <трек>` за один вызов показывает уровень после каждого плагина, а
`reamix trim` сам меряет источники и ставит тримы одной правкой. Замер — стемы до фейдера
с временно выключенными плагинами (`rx.scratch`), поэтому работает и там, где обработка
уже стоит. Это отменяет «отвергнуто: отдельная команда» из предыдущей записи.
Средний уровень для трима — не LUFS, а невзвешенный, в шкале VU: K-взвешивание занижает
бочку и бас на несколько дБ (вживую: бочка −9,9 против −14,2 LUFS). Сдвиг громкости на
плагине, наоборот, считается в LUFS: там важно, что слышит человек при сравнении.
Дорожки, где после трима уже стоят плагины, `reamix trim` без `--with-fx` не трогает:
трим изменит работу компрессоров и сатурации.
Отвергнуто: автоматически компенсировать выход плагина — у каждого плагина свой параметр
выхода, выбирает его Claude; компенсация фейдером при триме — в основном флоу трим стоит
до баланса.

## 2026-10-02 — Замысел: свободный вопрос последним и план частей
Вопросы с вариантами узнают только то, о чём Claude догадался спросить. Поэтому первую
порцию вопросов о замысле закрывает свободный: человек рассказывает о треке своими словами.
Там же Claude сам предлагает план частей — чем куплет, припев и остальные части отличаются
по ширине, АЧХ, плотности и пространству: без этого контраст частей появляется случайно, на
этапе автоматизации, когда панорама и пространство уже сделаны. План — замысел в
`docs/architecture.md` трека; исполняется на этапах 2–5, проверяется анализом по регионам.
Сильные переходы — не правило: какими им быть, решает человек.
