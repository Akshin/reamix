# Архитектура

## Общая схема

```
Claude Code (в папке трека)
   │  reamix <команда>
   ▼
CLI (Python) ── .ipc/request.lua ──▶ мост (Lua внутри REAPER) ──▶ API REAPER
   ▲                                      │
   └────────── .ipc/response.json ◀───────┘
   │
   ▼
<папка трека>/.reamix/   снимки состояния, журнал правок, рендеры, отчёты анализа
```

Мост — тонкий исполнитель: получает Lua-код, выполняет его в REAPER, возвращает результат.
Вся предметная логика — в `bridge/lib.lua` (таблица `rx`) и в CLI. Пакет команд — это
несколько вызовов `rx.*` в одном запросе; отдельного языка команд нет.

## Протокол обмена

Одна пара файлов в `.ipc/` репозитория, один запрос за раз (CLI держит блокировку `.ipc/lock`).

1. CLI пишет `request.tmp` и переименовывает в `request.lua` — мост видит только целый файл.
2. Мост на каждом тике defer-цикла (~30 раз в секунду) пробует открыть `request.lua`,
   читает, удаляет, выполняет.
3. Ответ — `response.json`, тоже через переименование. CLI ждёт ответ со своим `id`.

Запрос — Lua-код с заголовками в первых строках:

| Заголовок | Что делает мост |
|---|---|
| `--@id <id>` | возвращает в ответе, чтобы CLI не принял чужой ответ |
| `--@project <папка>` | отказывает, если активный проект лежит не в этой папке (или выше неё) |
| `--@undo <описание>` | оборачивает код в undo-блок «reamix: описание»; при ошибке откатывает его |
| `--@snap <папка>` | снимает состояние треков в `<папка>/before` и `<папка>/after` |

Ответ: `{id, ok, result | error, rolled_back, snap_before, snap_after, project, rev, ms}`.
`rev` — счётчик изменений проекта REAPER: по нему видно, менялось ли что-то между запросами.

Каждые 2 секунды мост пишет `.ipc/alive.json` (проект, `rev`, время) — так CLI отличает
«мост не запущен» от «REAPER занят». Запрос, который мост не забрал до таймаута, CLI удаляет;
оставшийся с прошлого запуска мост удаляет при старте. Устаревшая правка не выполнится.

Скрипт моста работает в главном потоке REAPER: во время рендера и модальных диалогов он
не отвечает, CLI ждёт до таймаута.

## Три уровня данных

| Уровень | Что | Когда | Команда |
|---|---|---|---|
| Скелет | треки, папки, громкость, панорама, плагины в цепочках, посылы, огибающие (счётчики), маркеры | каждое обращение | `reamix state` |
| Детали | параметры плагина, точки огибающей | точечный запрос | `reamix fx`, `rx.env_read` |
| Аудио | рендеры и метрики | по задаче, с кэшем | `reamix analyze` |

На диск всё пишется без потерь, в вывод команд идёт сжатое представление: только отличия
от значений по умолчанию, отформатированные значения параметров, сводки вместо списков точек.

## Снимки состояния

Лежат в папке трека, в `.reamix/`:

```
chunks/<sha1>.rtrack     состояние одного трека — родной чанк REAPER (плагины со всем
                         внутренним состоянием, огибающие, айтемы), по хешу содержимого
snapshots/<время>-<№>-<вид>.json   состав снимка: трек → хеш чанка, плюс скелет
edits.tsv                журнал правок: снимок «после», описание, снимок «до», rev
```

Вид снимка: `before` и `after` (вокруг `reamix do`), `manual` (`reamix snapshot`),
`check` (`reamix changes`). Одинаковые состояния хранятся один раз: правка одного трека
добавляет один чанк. Если `rev` не сдвинулся с прошлого снимка «после», снимок «до» не
снимается — им служит предыдущий.

`store.diff` сравнивает два снимка: изменения скелета построчно по трекам; если скелет
одинаков, а хеш чанка другой — «внутреннее состояние» (параметры, точки, айтемы).

## Рендер и анализ

`reamix analyze` → `rx.render` → `analysis.analyze`:

1. **Рендер** идёт штатным рендером REAPER (действие 42230) с временно подменёнными
   настройками проекта: WAV 32-bit float, частота проекта, без хвоста и нормализации.
   Микс — один проход, стемы выбранных треков (после плагинов и фейдера) — второй.
   Настройки рендера и выделение треков возвращаются как были. Перед рендером всё медиа
   переводится в онлайн: пока REAPER неактивен, он держит источники отключёнными
   (настройка «Set media items offline when application is not active»), и рендер выходит пустым.
2. **Метрики** на каждый файл: интегральная громкость и LRA (BS.1770 / EBU 3342), ряды
   momentary и short-term с шагом 0,1 с, true peak (×4), crest, корреляция и ширина стерео,
   корреляция ниже 120 Гц, уровни в 9 полосах и в 30 третьоктавных, громкость по регионам.
   Уровни полос — RMS в дБFS.
3. **Маскирование** направленное: стем «накрыт», если в полосах, важных для него самого
   (в пределах 12 дБ от его самой громкой), другой стем звучит не тише чем на 6 дБ больше
   40% времени. Папка и её дорожки, посыл и получатель между собой не сравниваются.

```
.reamix/renders/<запуск>/    mix.wav, stem-NN.wav — кэш, хранятся два последних набора
.reamix/analysis/<запуск>/   report.json (все метрики), series.npz (ряды громкости и
                             третьоктавная спектрограмма каждого файла)
```

Проблемы привязаны ко времени проекта: места выше 0 дБFS на миксе (сколько и самые
сильные) и участки, где накрыта хотя бы половина полос диапазона (три самых длинных).

Кэш: ключ — хеши состояний треков + список треков + участок. Рендер сам меняет внутреннее
состояние части плагинов, поэтому в отчёт пишутся два ключа — до рендера и после.
По умолчанию анализируются треки верхнего уровня: стем весит около 23 МБ на минуту.

## Сравнение до и после

`reamix ab` переключает последнюю правку через undo/redo REAPER: мгновенно, точно и без
перезагрузки плагинов. В состоянии «до» правка лежит в redo, и любая новая запись в
истории её уничтожила бы. Поэтому мост помнит, какую правку слушают (ExtState `preview`),
и отклоняет правки и служебные действия, пока не дан вердикт: `ab after` или `undo`.
`reamix play` ставит границы цикла на участок и запускает воспроизведение; записей в
истории undo это не создаёт.

## Роутинг

`rx.folder` — новый трек-родитель над треками (`ReorderSelectedTracks`); `rx.bus` — трек,
в который треки шлют посылом, с отключённым выходом в мастер. `rx.sidechain(src, dst, fx)`
расширяет `dst` до четырёх каналов и шлёт `src` на каналы 3/4 до фейдера. У плагинов с
четырьмя входами выводы 3/4 уже читают эти каналы; остаётся включить внешний вход в самом
плагине — у плагинов Cockos функция делает это сама (`SignIn` = 2/1084), для остальных
возвращает параметры-кандидаты. В скелете такой посыл помечен `sidechain`.

## Райдинг громкости

`reamix ride`: рендер стема → ряд momentary-громкости (окно 0,4 с, шаг 0,1 с) → поправка
к медиане звучащих кадров, ограниченная `--max` и сглаженная `--smooth` → прореживание
(Рамер — Дуглас — Пекер, допуск 0,25 дБ) → TSV в `.reamix/rides/` → `rx.env_write` с
`add = true` одним undo-блоком → повторный рендер и разброс громкости до и после.
Точки идут из Python в Lua файлом, мимо Claude. Кадры тише 30 LU от максимума считаются
паузой: поправка там нулевая, шум между фразами не поднимается. `add = true` прибавляет
поправку к существующей кривой, сохраняя её точки.

С `--vs-mix` цель другая: постоянное расстояние между треком и остальным миксом. Остальной
микс — рендер с заглушённым треком внутри `rx.scratch`; он от правки трека не меняется,
поэтому рендерится один раз.

## Фаза между дорожками

`reamix phase`: стемы дорожек → взаимная корреляция в окне ±20 мс (по сигналу ниже 2 кГц).
Отдаёт корреляцию как есть, лучший сдвиг и корреляцию при нём, знак (полярность) и
«низ в сумме» — уровень суммы ниже 200 Гц относительно суммы мощностей: +3 дБ в фазе,
0 у независимых, минус при вычитании.

## Сравнение с референсом

`reamix reference <файл>`: ffmpeg приводит файл любого формата к float WAV, к нему
применяются те же метрики, что к миксу. Полосы сравниваются относительно общего уровня
каждого файла. Метрики референса кэшируются в `.reamix/reference/`.

## Параметры плагинов

Чужие плагины отдают параметры как 0..1 плюс текст, которым сами показывают значение.
Шкалу знает только плагин, поэтому значение «как на экране» ставится подбором:
`rx.fx_set(..., {fmt = '2.5 kHz'})` делит отрезок 0..1 пополам, пока показание плагина не
совпадёт с целью. Цель и показания приводятся к одной шкале (kHz → Гц, ms → с).
Показание берётся через `TrackFX_FormatParamValueNormalized` — плагин отвечает, как покажет
значение, а сам параметр не трогается; работает в VST, VST3, AU, CLAP и JS.

Переключатели («Bell», «External Input») ставятся по названию: `{text = 'Low Cut'}` проходит
диапазон в 401 шаг, собирает разные показания и ставит середину нужного варианта.

После записи `set_norm` проверяет, что плагин принял значение. CLAP-плагины применяют
изменения в аудиопотоке — с задержкой в несколько миллисекунд, а при закрытом
аудиоустройстве не применяют вовсе; тогда устройство открывается на время записи.

Чтение параметров: `reamix fx` показывает только те, что отличаются от значений по умолчанию
(у Pro-Q 4 — 4 строки вместо 740). API REAPER значений по умолчанию не отдаёт, поэтому
`rx.fx_defaults` один раз создаёт чистый экземпляр плагина на временном треке и стирает
след через `rx.scratch` (undo-блок, который тут же откатывается). Результат кэшируется в
`~/.reamix/defaults/` — по файлу на плагин, общий для всех проектов.

## Огибающие

Встроенные огибающие трека (громкость, панорама, mute) в REAPER есть всегда, но выключены;
`rx.envelope(..., create)` включает и показывает их. Огибающую параметра плагина создаёт
`GetFXEnvelope`. Значения громкости хранятся в шкале фейдера — `rx.env_read` и
`rx.env_write` переводят через `ScaleFromEnvelopeMode` / `ScaleToEnvelopeMode`.
При включении огибающей громкости REAPER переносит в неё уровень фейдера, а фейдер
становится тримом поверх огибающей.

## Каталог плагинов

Каталог, умолчания параметров и предпочтения — данные пользователя, лежат в `~/.reamix/`
(`REAMIX_DATA`), а не в репозитории: у каждого свои плагины.

`reamix plugins scan` читает списки, которые REAPER сам собирает при сканировании папок
плагинов, и сверяет их с файлами в `/Library/Audio/Plug-Ins` и `~/Library/Audio/Plug-Ins`.
Один плагин в нескольких форматах — одна строка, предпочтение VST3 → VST → CLAP → AU.
Категории — из `reaper-fxtags.ini`, отметка «недавно использовался» — из `reaper-recentfx.ini`.
Колонка `add` — строка для `rx.fx_add`.

## Документация в папке трека

`reamix init` кладёт в папку трека `CLAUDE.md` и `docs/` (CURRENT, DECISIONS, architecture).
Туда пишется только то, чего нет в REAPER: замысел, вкус, причины, отвергнутые попытки.
Уровни, параметры и цепочки читаются мостом вживую и в документацию не дублируются.
