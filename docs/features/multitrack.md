# Проект из мультитрека

Основной способ начать трек: человек кладёт в папку файлы дорожек, `reamix multitrack`
собирает из них проект REAPER для сведения. Для Claude — раздел «Новый трек из мультитрека»
в `skill/SKILL.md`.

## Флоу

```
папка трека/
  Song KICK.wav, Song VOX.wav, gtr/Song GTR L.wav …   мультитрек, как его положил человек
  Song.als                                             необязательно: темп, размер, регионы
  reaper/Папка трека.rpp                               проект для сведения
  reaper/.reamix/multitrack/scan.json, layout.txt      осмотр и раскладка
  references/                                          референсные треки: папку создаёт сборка
  CLAUDE.md, docs/                                     память о треке (reamix init)
```

1. `reamix multitrack` — осмотр: таблица файлов и черновик раскладки.
2. Claude спрашивает темп и размер, если их неоткуда взять, переписывает раскладку под
   сведение (папки-шины, понятные имена, регионы) и показывает её человеку.
3. `reamix multitrack --build` — пишет `.rpp`, открывает его в REAPER и сохраняет.
4. `reamix init`, `reamix analyze` — анализ остаётся у Claude как точка отсчёта: материал
   сырой, пересказывать его «проблемы» незачем. Человеку — первые вопросы этапа «Замысел»
   (этапы сведения — в скилле).

Сессия Claude открыта в папке трека, а проект лежит в `reaper/`: команды `reamix` находят
его сами (`cli.track_dir`), защита от чужого проекта сверяет активный проект с `reaper/`.

## Осмотр

Что считается для каждого файла (`multitrack.measure`) и зачем:

| Поле | Что это | Что по нему видно |
|---|---|---|
| каналы | моно, стерео, `стерео=моно` (каналы совпадают) | моно-источник в стереофайле |
| пик, RMS | дБFS | запас по уровню, пустые файлы (пик ниже −80) |
| crest | пик минус RMS | ударное (больше 15) или ровный звук (меньше 8) |
| звучит | первое и последнее место громче «пик − 50 дБ» | где дорожка есть в треке |
| низ/верх | доля энергии ниже 250 Гц и выше 4 кГц | бочка и бас против тарелок |

Этого хватает, чтобы разложить дорожки с именами вроде `new` или `Audio 12`, не слушая их.
Измерения кэшируются в `scan.json` по размеру и времени файла: повторный осмотр мгновенный.

Не осматриваются: `reaper/`, `references/`, `Backup/`, служебные папки Ableton, а в папке с `.als` — ещё
и `Samples/` (там сэмплы проекта, а не мультитрек). Общее начало имён файлов убирается:
при экспорте дорожек Ableton ставит туда имя проекта.

## Из .als

Если в папке лежит проект Ableton (берётся самый свежий), из него читаются:

- темп и размер — в шапку раскладки. Темп считается постоянным: при автоматизации темпа
  берётся начальное значение и осмотр об этом предупреждает;
- локаторы → регионы: локатор — точка, регион идёт от него до следующего, последний — до
  конца записи; участок до первого локатора — регион «начало»;
- группы дорожек — подсказка для раскладки, если имя файла однозначно совпало с именем
  дорожки. Одноимённые дорожки (`new`, `new`) по имени файла не различить.

## Раскладка

Текстовый файл, который правит Claude:

```
темп 92
размер 4/4
регион 0:00.000 0:20.870 Intro

DRUMS
  Kick <- Song KICK.wav
Bass <- Song BASS.wav
```

Строка без `<-` — папка, отступ в два пробела — вложенность, `Имя <- файл` — дорожка.
Время региона — секунды или `м:сс.ммм`. `темп ?` — темп неизвестен, сборка откажется.
Осмотр пишет черновик один раз и поправленную раскладку не затирает (`--force` — заново).

Структуру папок решает Claude вместе с человеком, а не код: правила — в скилле. Сборка
проверяет только формальное: файл есть, не пустой, не стоит дважды; файлы, не вошедшие в
раскладку, перечисляет.

## Проект

Одна дорожка на файл, айтем с нуля на всю длину файла, фейдеры в нуле, панорама в центре:
баланс уже в файлах. Папки верхнего уровня получают цвет, дорожки внутри — тот же. Пути к
файлам относительные (`../Song KICK.wav`). Плагинов нет, поэтому сборке REAPER не нужен.

Открытие (`multitrack.open_in_reaper`):

| REAPER | Что делает команда |
|---|---|
| закрыт | запускает его с проектом (`open -a REAPER файл`), ждёт мост, сохраняет |
| открыт, активная вкладка пустая | открывает проект в ней через `bridge/import.lua` и сохраняет |
| открыт, во вкладке другой проект | ничего не трогает: вкладку или файл открывает человек |

Сохранение сразу после открытия нужно, потому что проект, открытый из написанного текстом
файла, REAPER считает изменённым.

## Референсы

Сборка создаёт в папке трека `references/`. `reamix reference` ищет файл там: по имени или
его части, а без имени берёт единственный файл из папки.

## Проверено вживую (REAPER 7.81, пробная папка)

Сборка при закрытом REAPER: он запустился с проектом, мост поднялся, проект сохранён — всё
за 2 секунды. В REAPER встали вложенные папки, 10 регионов из `.als`, айтемы на всю длину
файлов; `reamix state` из папки трека нашёл проект в `reaper/`.

## Не проверено

- Настоящий экспорт из Ableton: как он называет файлы одноимённых дорожек и совпадают ли
  имена файлов с именами дорожек в `.als`.
- Форматы кроме WAV: `.m4a` не читается (libsndfile), `.mp3` зависит от версии библиотеки.
